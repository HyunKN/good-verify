# good-verify

사람이 수행한 QA를 재현 절차, 테스트, 검증 근거로 남기는 **로컬 검증 워크벤치**입니다. 기록과 재실행에는 AI 모델이나 API 키가 필요하지 않습니다.

현재 상태: **0.1.0-alpha.1**. Chromium 기반 웹 QA를 지원하며, 모든 플랫폼이나 실제 외부 서비스의 상태까지 복원하는 도구는 아닙니다.

## 시작하기

### Windows에서 더블클릭 실행

Node.js 22.14 이상을 먼저 설치한 뒤 clone한 폴더의 `start.cmd`를 더블클릭합니다. 고정 버전 pnpm으로 의존성·Chromium을 준비하고 빌드한 뒤 브라우저를 엽니다. 최초 준비에는 인터넷이 필요합니다. 실행 창은 유지하고, 종료할 때 Ctrl+C를 누릅니다. 설치형 앱이나 백그라운드 서비스는 아닙니다.

업데이트는 실행 창을 종료하고 사용자 데이터 디렉터리를 백업한 뒤 `update.cmd`를 더블클릭합니다. 로컬 변경이 있으면 중단하며, upstream을 fast-forward로만 반영합니다. 준비 중 실패하면 오류를 해결한 뒤 다시 실행하세요. 자동 rollback이나 데이터 migration은 하지 않습니다. 사용자 데이터는 저장소 밖에 유지됩니다.

아래 터미널 실행 방식도 지원합니다.

문제 진단 시 `node scripts/launch.mjs --check-only`는 Node 버전만 확인하고, `--prepare-only`는 설치·빌드까지만 수행합니다. 별도 포트가 필요하면 `--port=4397`을 사용할 수 있으며 `--no-open`은 브라우저 자동 열기를 생략합니다. 업데이트에도 동일한 포트를 지정하세요. 기본 더블클릭 실행은 4318 포트를 사용합니다.

Node.js 22.14 이상과 pnpm 11.19가 필요합니다. 최초 설치는 패키지와 Chromium 다운로드를 위해 네트워크를 사용합니다.

```sh
git clone https://github.com/HyunKN/good-verify.git
cd good-verify
pnpm install --frozen-lockfile
pnpm browser:install
pnpm build
pnpm start
```

브라우저에서 `http://127.0.0.1:4318`을 엽니다. `localhost` 대신 표시된 loopback 주소를 사용하세요. 개발 중에는 `pnpm dev`로 실행하며 UI 주소는 `http://127.0.0.1:5173`입니다.

1. **프로젝트 연결**에서 이름과 폴더를 입력하고 **프로젝트 설정 찾기**를 누릅니다. 찾은 검사 중 연결할 항목만 선택하고 실제 실행 URL을 확인하세요. Node 프로젝트가 아니거나 제안이 없으면 직접 입력할 수 있습니다. 대상 앱의 개발 서버는 먼저 직접 실행하세요. 제안된 명령도 신뢰하는 프로젝트에서만 등록하세요.
2. **작업과 완료 기준**에 요구사항과 관찰 가능한 완료 기준을 남깁니다. 작업 없이 자유 QA를 먼저 시작해도 됩니다.
3. **QA 기록 → QA 시작**으로 전용 Chromium을 엽니다. 평소처럼 조작하고 브라우저 상단에서 문제 또는 검증 지점을 표시합니다.
4. 기록을 종료하고 **시나리오 초안**을 만듭니다. 단계와 기대 결과를 검토한 다음 재실행합니다.
5. 통과한 실행 또는 명시적인 수동 확인 근거로 시나리오를 등록합니다. 작업에 필수 검사를 연결하고 현재 코드의 리뷰를 남깁니다.
6. 보고서에서 첨부를 미리 보고 선택한 뒤, 제품 저장소 **밖**으로 내보냅니다.

검증 지점은 관찰한 화면을 자동 정답으로 채택하지 않습니다. 사용자가 기대값을 입력해야 합니다. 미지원 조작이 있는 흐름은 자동 통과 대신 수동 확인으로 남습니다.

## 일반 샘플

별도 터미널에서 `pnpm sample`을 실행한 뒤 `http://127.0.0.1:4320/`을 연결하세요. 샘플 소스 폴더는 `samples/editor`입니다.

샘플에는 제목 편집을 취소할 때 변경값을 저장하는 의도적인 버그가 있습니다. 제목 입력 → 취소를 기록하고 `saved-title` test ID의 텍스트가 `처음 제목`이어야 한다고 지정하면 실패를 재현할 수 있습니다. `SAMPLE_FIXED=1`로 샘플 서버를 다시 시작하면 수정된 동작을 시험할 수 있습니다. 이 토글은 데모용 환경 변경이지 소스 수정의 증거가 아닙니다. 자동 E2E에서는 코드 상태 변경도 별도로 검증합니다.

## 데이터와 안전 경계

- 설정·JSONL 조작 기록·첨부는 OS 사용자 데이터 디렉터리 아래 `good-verify/projects/<프로젝트 UUID>`에 저장됩니다. 실제 경로는 실행 환경의 `LOCALAPPDATA` 또는 `XDG_DATA_HOME`에 따라 달라집니다.
- `GV_DATA_DIR` 또는 `--data-dir`로 다른 **저장소 외부** 위치를 지정할 수 있습니다. 프로그램 업데이트와 사용자 데이터를 분리하세요.
- 전용 브라우저는 개인 브라우저와 분리됩니다. 사용자가 저장한 브라우저 준비 상태는 `private/browser-state.json`에 보관하며 보고서에 포함하지 않습니다.
- 서버는 loopback에서만 실행합니다. 로컬 토큰을 사용하며 웹 요청의 Host와 Origin을 검사합니다. 토큰은 `runtime.json`에 저장되고 화면이나 일반 출력에는 표시하지 않습니다. 브라우저 세션은 서빙된 화면의 1회용 nonce로 시작하며, 쿠키에는 토큰 대신 폐기 가능한 세션 식별자가 들어갑니다. loopback은 같은 사용자뿐 아니라 이 컴퓨터의 다른 로컬 계정에서도 접근할 수 있습니다.
- 신뢰하는 프로젝트와 명령만 등록하세요. 명령은 프로젝트 폴더에서 사용자의 OS 권한으로 실행됩니다. OS 사용자 자체를 격리하는 보안 sandbox가 아닙니다.
- 비밀 입력과 네트워크 본문을 기록하지 않고 알려진 인증 패턴을 가립니다. 임의의 화면·자유 텍스트·로그에 포함된 모든 비밀을 자동 감지할 수는 없습니다. 공유 전 반드시 검토하세요.

## 업데이트

서비스를 종료하고 사용자 데이터 디렉터리를 별도 위치에 백업한 뒤 진행합니다. 작업 트리에 본인 변경이 있다면 먼저 보존하세요.

```sh
git pull --ff-only
pnpm install --frozen-lockfile
pnpm browser:install
pnpm build
pnpm start
```

스키마 v1을 읽으며 지원하지 않는 버전은 덮어쓰지 않고 거부합니다. 현재 자동 마이그레이션은 없습니다. 재시작 시 중단된 QA는 불완전, 중단된 실행은 실행 불가로 복구합니다.
