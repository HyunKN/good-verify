# Alpha 범위와 검증 현황

## 제공하는 기능

- 외부 프로젝트 연결·설정 변경, 요구사항·완료 기준·기존 검사 연결
- 전용 Chromium QA 기록, 문제·검증 지점 표시, 불완전 세션 복구
- 조작에서 파생한 시나리오, 명시적 assertion, 재실행과 등록 검토
- 실행 이력·코드 식별·당시 테스트 snapshot·수동 근거·리뷰·완료 판정
- 별도 실행 가능한 Playwright 초안, JSON·Markdown·오프라인 HTML·이슈 템플릿
- 프로젝트 격리, Origin·토큰 검사, 선택적 비공개 브라우저 준비 상태, 연결 서버 로그
- 소스 설치, CLI·API, 일반 샘플, 자체 검사 및 CI 구성

## 확인한 것

Windows / Node 22.14 / pnpm 11.19 / Playwright Chromium 환경에서 단위·서비스와 브라우저 검증을 수행한다. 정확한 최종 개수는 해당 실행 결과를 기준으로 보고한다.

- 일반 버그의 수정 전 실패 → 수정 후 통과 → 등록 → 완료 판정 → 보고서
- 한국어 IME 이벤트, 연속 클릭, 선택, 체크, 미지원 조작과 비밀 입력 처리
- 새 context 격리와 명시적인 private storage state 복원
- 생성 테스트를 별도 임시 프로젝트에서 good-verify 소스 import 없이 실행
- 명령 실패·취소·타임아웃, locator 모호성, 준비 실패, 중단 실행·잘린 JSONL 복구
- 코드·기준 변경 무효화, 미실행 assertion 거부, 과거 시나리오 snapshot
- 실제 CLI로 빌드된 웹 UI 시작, 프로젝트 연결·기록·검사·재시작 후 데이터 열기
- 소스 snapshot을 임시 Git 저장소에서 공백이 포함된 새 경로로 clone하여 실행 스크립트의 의존성 준비·Chromium 확인·빌드·서비스 실행 확인. 실행 중 업데이트 거부, fast-forward 업데이트 후 재실행, 기존 프로젝트·검사 기록 조회와 기록 파일 SHA-256 일치 확인. 현재 Windows의 Node와 패키지/브라우저 캐시를 사용했으며 새 PC나 GitHub 배포본 검증은 아니다.
- 외부 개발 프로젝트에서 실제 저장 경로를 사용한 제한된 기록·재실행·보고서 전달. 대상별 기록과 설정은 저장소 외부에만 보관

## 아직 일반화하거나 완료로 주장하지 않는 범위

1. **브라우저 기록의 완전성:** 모든 웹앱·프레임·팝업·파일 흐름에 대해 무손실을 보장하지 않는다. 페이지 전환 타이밍과 사용자 정의 위젯은 원본 단계와 기대값을 검토해야 한다. Canvas·복잡한 드래그·프레임은 수동 구간이다.
2. **환경 재현:** 브라우저 상태는 서버 DB, 실시간 이벤트, 외부 응답, 환경 변수, ignored 파일을 복원하지 않는다. 실제 계정·결제·외부 이벤트 검증은 별도 범위다.
3. **개인정보:** 비밀번호 필드와 알려진 패턴을 가리지만 임의 화면·자유 텍스트의 모든 비밀을 찾지는 못한다. 첨부는 사람이 공유 전에 검토한다. raw Playwright trace는 인증 정보 포함 위험 때문에 수집하지 않는다.
4. **로그:** 연결한 로그 파일의 마지막 최대 128KiB를 수집한다. 분산 추적이나 서버 로그의 실시간 스트리밍·정확한 요청 상관관계는 제공하지 않는다.
5. **사용성:** 프로젝트 폴더 선택은 경로 입력이다. package.json에서 검사·실행 명령과 기본 URL을 제안하고 사용자가 선택해 저장할 수 있다. URL은 실제 실행 상태를 확인한 값이 아니다. 시각적 단계 편집기·자연어 assertion 변환은 아직 없으며 일부 설정은 JSON 편집이 필요하다.
6. **CI와 배포:** CI 파일 작성은 원격 CI 성공이 아니다. macOS·Linux와 완전히 깨끗한 머신 설치, 서명된 설치 파일, 조직 사용·권한 관리, 대용량 기록의 장기 운영은 별도 검증이 필요하다.
7. **접근성:** 데스크톱·모바일 캡처와 기본 키보드 동작을 확인한다. 모든 화면의 확대·스크린 리더·전체 대비 검수가 끝났다는 뜻은 아니다.

## 다음 릴리스의 우선순위

원본 이벤트 순서와 페이지 전환의 추가 회귀 사례 → 설정 발견과 단계 편집 UX → 실행 결과를 기다리는 CI CLI → 데이터 migration·백업·정리 UX → 다양한 프로젝트에서의 재현 성공률 측정 순서다. 플랫폼 수를 늘리기 전에 두 번째 프로젝트에서도 공통 코드 변경 없이 핵심 흐름이 성립하는지 확인한다.

최종 제품 판단은 테스트 개수보다 다른 사람이 보고서만 보고 조건을 이해하고 재현·재검증할 수 있는지로 한다. 현재 산출물은 그 흐름을 제공하는 alpha이며 계획의 모든 후속 일반화가 끝난 제품은 아니다.
